## 0. 路线图的基本立场

1. **里程碑不是时间表**。工作量以"人日"给出量级估算（单人 + AI 辅助），不承诺日历日期。每个里程碑都是**可中断点**：做到哪一步停下，都是一个能用的东西。
2. **一次只开一条链路**。v0.1 只做喝水；v0.2 才让活动成为第二个场景；v0.3 才让外部日历成为第三种触发来源；v0.4 才让"你自己定的时刻"成为第四种。任何"顺手把完整 CalDAV 也做了"的念头都推后。
3. **每个里程碑都有一个可验收的产物**，不是"写完了代码"。验收不过就不进下一个。
4. **商业决策（定价、商店、付费包）一律推迟到有真实用户之后**。当前全部功能免费，代码里不出现任何付费、市场、下载相关的东西。

## 3. v0.1 — 只做喝水

### M1 骨架（1–2 人日）— 完成

**交付物**：SwiftPM 工程、`Info.plist`（`LSUIElement`）、`scripts/bundle.sh`、`Makefile`、菜单栏图标、popover 空壳、`AppState` 持久化。

**验收**
- `make app` 一条命令产出 `Barge In.app` 并能启动
- 启动后无 Dock 图标，菜单栏有图标，点开能看到空 popover
- 改一个状态 → 退出 → 重启，状态还在

### M2 喝水闭环（2–3 人日）— 完成

**交付物**：配额状态（目标/单杯/已喝/跨日重置/达标静默）、`Schedule`（间隔 + 指定时刻）、工作时段、休息日、`nextFireDate` 定时器与唤醒/改时重算、popover 进度显示。

**验收**
- 改设置后下一次触发时间立即正确
- 达标后当天不再提醒；次日自动重置
- 非工作时段、休息日、暂停中均不提醒
- 唤醒后若已过点，只补触发一次

**风险**：跨日、睡眠、时区跳变是这类 App 的三个经典坑。全部在 `Schedule` 一个地方处理，不在 UI 层兜底。

### M3 呈现体验（3–4 人日）— 完成

**交付物**：`NSPanel` 多屏覆盖（`screenSaver` 层级、跨 Space）、卡片样式、满屏重复大字的全屏样式、音效（含渐强）、三个动作（完成/推迟/中断）、双击 Esc 中断。

**验收**
- 多显示器全覆盖；切 Space 不丢失；全屏 Space 内能弹出
- 三种结束方式各自生效；中断零等待
- 任何档位下单击 Esc 都不中断，快速双击 Esc 可立即中断（锁定期间照旧）；强硬档的"喝了"与 × 在 5 秒锁定走完后可用
- 提醒展示中再次到点不叠面板
- 拔插显示器后面板集合正确重建

**风险**：这是唯一的"看起来简单、坑最深"的里程碑。窗口层级与 Space 行为以实测为准。

### M4 账本记录（1–2 人日）— 完成

**交付物**：账本（记录）模型——每个场景当天的进度、完成次数、跳过次数与已处理提醒；按场景各一份；次日归零；不做历史与统计；界面不展示跳过次数。

**验收**
- 跳过与完成都只写入记录，不改变下一次提醒的呈现
- 各场景的记录互不牵连；次日归零；重启后记录还在
- 提醒层、popover 与设置里没有"升级说明"
- `--selftest` 覆盖记录的写入、次日重置与场景隔离

### M5 设置与引导（2–3 人日）— 完成

**交付物**：设置窗口全部配置项、首次启动一步完成预设选择（默认大字墙）、开机自启、免打扰 1 小时。

**验收**
- 所有配置即时生效，没有保存按钮
- 首次启动一步完成，不做多步引导
- 重启 App 后所有配置保持

### M6 公开仓库发布 v0.1（1–2 人日）— 完成

**交付物**：公开仓库（源码、文档、issue）、README（截图、安装与构建说明）、`.gitignore`、Release 附 `.app` 压缩包。0.4.1 起源码并入同一个仓库，MIT（[ADR-0005](adr/0005-open-source.md)）。

**验收**
- 陌生机器下载 `.app` → 能运行
- 公开仓库里有源码、构建、安装与已知边界说明，`make app` 能从干净检出产出一份可运行产物
- README 里没有任何需要用户关掉安全机制的步骤
- 自己连续使用 7 天没有关掉提醒

**发布门（决定是否继续投入）**

公开仓库发布后观察四周，三个问题全部为"是"才继续：

1. 我自己还在用它吗？
2. 有陌生人提了**具体的**功能请求（而不是 star）吗？
3. 有没有人问"有没有别的效果"（验证呈现层是商品这一核心假设）？

## 5. v0.2 — 多场景 + 活动

### M8 多场景 + 活动（4–6 人日）— 完成

**交付物**：SwiftPM 分包（`BargeInCore` / `SceneWater` / `SceneActivity` / `BargeIn`）、场景模型（`SceneID`/`SceneDescriptor`/`SceneConfig`）、活动场景、全局共享时间、按场景的队列与调度、popover 双场景、设置按场景切换、引导落到两个场景。

**验收**
- 两个场景各自调度、各自记录，互不牵连

- 每个场景最多一条待处理；唤醒只补同一天、工作时段内、未暂停的到点
- 停用一个场景只停它的调度，另一个照常
- `make app` / `--selftest` / `--snapshot` 全部通过

## 6. v0.3 — 日程

### M9 日程（9–13 人日）— 完成

**前置**：v0.2 已完成；产品方向已锁定（见 [product.md §8](product.md)）——只读订阅、事件前置提醒、不写回、不做完整 CalDAV。

**交付物**

- `SceneID.schedule` + `SceneTrigger`（`rhythm` / `events`），`FirePlan` 支持事件来源与"开始超过 10 分钟不补"
- `SceneSchedule` target：iCalendar 子集解析（行折叠与转义、`UID`/`SUMMARY`/`DTSTART`/`LOCATION`/`RRULE`/`EXDATE`、`TZID`/UTC/`VALUE=DATE`）、`DAILY/WEEKLY/MONTHLY + INTERVAL + COUNT/UNTIL/BYDAY` 展开、事件窗口 `[now-1d, now+8d]`
- 传输一（ICS）：`GET` + 可选 Basic Auth、`webcal://` 改写、`Content-Type` 校验
- 传输二（CalDAV）：`PROPFIND` 发现日历集合 → 用户勾选 → `REPORT calendar-query` 拉事件；钉钉 `calendar.dingtalk.com` 为首个验收目标，企业微信/飞书/iCloud 私有/Nextcloud 同构
- 订阅：多条来源（地址或 CalDAV 账户）、密码进 Keychain、串行请求、30 分钟刷新 + 唤醒刷新 + 手动刷新、失败退避到 4 小时、取回的日历文本缓存到 `Application Support`
- 失败降级：读缓存继续提醒 + 设置页与 popover 标注过期；认证/格式/网络三类错误分别给文案
- 队列：去重键改为 `ReminderKey(scene, eventKey?)`，日程按事件各一条
- 已提醒去重：`handledEventKeys` 落盘按天清理；推迟用 `snoozedUntil`（进程内）
- UI：设置第 4 个 tab（订阅列表 + 前置 + 预设，无节奏卡）、popover 日程行、日程卡预览占位事件
- 默认值：场景出厂停用、前置 5 分钟、默认大字墙 · 标准
- `--selftest`：解析、展开、豁免规则、按事件去重的队列、失败降级、已提醒不重弹
- `--calendar-probe`：`ics <url>` 或 `caldav <server> <username> --discover`，只取一次并打印解析结果，用于排查订阅

**验收**

- **真实钉钉 CalDAV 账号**：填入服务器/账号/密码 → 发现日历 → 拉到事件 → 事件开始前 5 分钟提醒；在钉钉里改事件时间 → 30 分钟内同步
- 填真实 Google 秘密地址（ICS 传输）→ 同样命中正确时刻
- 断网重启 → 仍按缓存提醒，设置页明说数据可能过期
- 地址写错 / CalDAV 密码错 / 返回 HTML → 分别提示"地址无效""认证失败""格式无法解析"，不弹提醒也不崩
- 19:00 的会议、周六的日程照常提醒；免打扰期间不提醒
- 两个事件相隔 5 分钟 → 逐条呈现，"还有 N 个"正确
- 全天事件不提醒；已开始超过 10 分钟的事件不补弹
- 同一事件重启 App 后不重弹
- `make app` / `--selftest` / `--snapshot` 全部通过

**不做**：CalDAV 写操作（PUT/DELETE/MKCALENDAR）、`sync-token` 增量、OAuth、Graph、写回日历、全天事件、参会人与会议链接。

**风险**

- **覆盖缺口**：CalDAV 覆盖钉钉/企业微信/飞书/iCloud 私有/Nextcloud，但 Google 私有与 Outlook 私有仍要 OAuth 或 Graph。文档明写支持范围，不承诺通吃。
- **钉钉 CalDAV 已实测**：2026-11 用真实账号跑通「发现 → REPORT → 解析 → 提醒」全链路；企业微信、飞书、腾讯会议仍以公开前的实测为准，跑不通先修传输层，不靠改叙事绕过。
- **解析长尾**：真实 `.ics` 里格式千奇百怪（非标准时区、非法折行、缺少 `DTEND`、`RRULE` 长尾）。策略是"解析不出的单条事件跳过并计数，整本失败才报错"，不让一条脏数据拖垮整天。
- **联网叙事**：产品第一次联网，容易被当作"开始变味"。对策是只读、默认关、凭据进 Keychain、README 明写。
- **地址失效**：秘密地址被重置后用户只会看到"没日程了"。对策是错误原因与"今天真没日程"分开说。

## 7. v0.4 — 闹钟

### M10 闹钟（3–5 人日）— 完成

**前置**：v0.3 已完成；产品方向已锁定（见 [product.md §8](product.md)）——闹钟是你自己定下的时刻，受通用时间约束，不做待办。

**交付物**

- `SceneID.alarm` + `SceneTrigger.alarms`（独立取值，不复用 `events(leadMinutes:)`，理由见 [ADR-0002](adr/0002-alarms-vs-calendar.md)）
- `SceneAlarm` target：闹钟模型（时刻、内容、每天 / 仅一次、开关）、逐字段容错、场景样例值
- 场景状态：闹钟列表 + 已提醒时刻（按天清理），过期的一次性闹钟次日清掉
- 调度：每天铺点跳过休息日；一次性只铺那一天；候选时刻先按通用时间筛过，无效条目不参与
- 补发：一次性 60 分钟窗口、被当天工作时段结束封顶；重复错过不补；免打扰按不在场处理
- 队列：去重键 `(场景, 闹钟标识 + 发生日期)`，昨天的完成不影响今天
- 完成「知道了」/ 推迟 5 分钟 / 中断；账本按场景记录；一次性关闭后从列表消失
- UI：设置第五个 tab、行内编辑（内容、时刻、每天/仅一次、7 天内日期）、无效标琥珀并写原因、删除二次确认；popover 只读行
- 通用时间说明改成"喝水、活动与闹钟共用"

**验收**

- 新建一条 11:30 的每天闹钟 → 到点用大字墙呈现，大字词是内容、进度行是时刻
- 跳过它 → 只写入记录，不改变下一次呈现；完成 → 也只记录；账本按场景各一份
- 19:30 的闹钟 → 行内标「不在工作时段内，不会响」，不触发、不计入今天、不记账本
- 一次性闹钟落在周六 → 标「那天是休息日，不会响」
- 改工作时段 → 已有闹钟立即重判，不需要重建
- 离开工位错过 11:30，11:50 回来 → 一次性补一次；12:40 才回来 → 作废
- 免打扰 1 小时期间到点 → 结束时仍在窗口内则补一次
- 一次性闹钟关闭或次日零点后从列表消失；每天闹钟保留
- 同一时刻两条闹钟 → 逐条呈现，显示"还有 N 个"
- `make app` / `--selftest` / `--snapshot` 全部通过

**不做**：选星期几、节假日日历、自定义铃声与贪睡间隔、闹钟分组与历史、系统闹钟导入、iCloud 同步、任何待办语义（勾选完成、截止日、优先级、清单排序）。

**风险**

- **变成待办**：能自己写一句话提醒，用户会往里塞"下个月交材料"。对策：一次性只收未来 7 天；没有勾选、截止日与历史；过期即消失；文档明写边界。
- **无效条目被读成坏了**：时刻越界与休息日冲突都会标「不会响」，文案必须写清原因，否则用户以为是 bug。
- **四个场景太吵**：出厂停用、加第一条才提示开启；各场景的默认时刻错开。

### M13 更新检查（1–2 人日）— 完成

**前置**：v0.4 已发布；分发只有 GitHub Releases，没有商店自动更新。

**交付物**

- `UpdateChecker`：读 GitHub releases atom 拿最新版本号与发布说明；逐段数字比较版本；启动后一次 + 每 24 小时一次；关掉即停表
- 温柔更新通知：复用温柔卡（右上角、提示音、不抢焦点），只说「Barge In 有新版本 x.y.z」；点卡片打开设置·通用；同一版本只通知一次
- 通用页：「自动检查更新」开关（出厂开）与版本卡（检查 / 可更新 / 下载 / 安装 / 失败；有新版时写出这次更新了什么并给发布说明入口）
- 一键安装：下载 → 解包 → 校验 bundle id、版本与签名 → 退出后替换当前 `.app` 并重新打开；失败还原旧版本
- `AppState` 加 `checkForUpdates` 与 `lastNotifiedVersion`，逐字段容错
- 文档与官网同步「日程订阅 + 更新检查」的联网口径，记录 [ADR-0006](adr/0006-update-check-network.md)

**验收**

- 0.4.1 的机器检测到 0.5.0 → 右上角出现温柔卡；点卡片落在设置·通用的版本卡，摘要与发布说明入口都在
- 关掉「自动检查更新」→ 不再自动联网；手动检查仍可用
- 点「更新」→ 下载、校验、替换、重启，版本号变新；数据（`UserDefaults`）不丢
- 没有写入权限 / 不是 `.app` / 校验不过 → 版本卡写明原因并给手动下载，App 继续可用
- 同一版本不会重复弹卡；正在弹提醒或设置窗口开着时不叠卡
- `--selftest` 覆盖版本比较、feed 解析与摘要、两个新字段的默认值与落盘

**不做**：增量更新、回滚入口、渠道与灰度、后台静默替换、系统通知中心。

**风险**

- **更新装坏**：未公证、ad-hoc 签名，只能靠 bundle id + 版本 + 自身签名校验。对策：替换放在进程退出后由脚本做，失败还原；写入权限提前检查。
- **联网叙事**：多了一个联网功能。对策：只读、可关、设置页与 README 明写；不做版本人群统计。

## 8. v0.5 — 免费内容

### M11（3–5 人日）

**前置**：不做付费决策；只做预设格式与内置免费预设。

**交付物**：预设的自有格式（资源 + 参数，如确有必要）、内置免费预设若干、设置里的预设展示、文档说明如何新增预设。不做下载安装、不做市场、不做账号或校验。

**验收**
- 新增一套内置预设不需要改引擎代码
- 全部内容免费，界面没有任何购买、账号或解锁入口
- 预设随 App 分包分发，不引入网络请求

**风险**：没有真实用户就先造内容体系，可能做了一堆没人用的预设；先把"呈现即产品"验证掉再加预设。

## 10. 始终不做

统计图表、连续达标天数、成就、云同步、账号、遥测、iOS 端、摄像头确认、Apple Watch、AppleScript/Shortcuts 钩子、全局快捷键自定义、会议/录屏自动避让、代码级插件系统；预设的安装与卸载、manifest、目录扫描、素材运行时、字号配置；日程的写回与编辑、全天事件提醒、参会人与会议链接；闹钟的选星期几、节假日日历、自定义铃声与贪睡间隔、分组与历史、系统闹钟导入；任何待办语义（勾选完成、截止日、优先级、清单排序）。

## 11. 延后项（等真实需求）

- **Google 私有 / Outlook 私有的取数**：前者要 OAuth 2.0 + 企业 MS 生态的 OAuth 客户端，后者只有 Microsoft Graph。它们是 v0.3 之后最可能被要求的一件事，但都不是"多写一个分支"的量级。
- **合并呈现**：同时到点只弹一次、把多个场景放进同一面板（含闹钟与日程挨着到点）。需要先定义"主场景 + 附加行"的呈现与记录规则。
- **优先级策略**：只提醒一条、其余记为已提醒。与"不静默丢弃"冲突，只有真实用户明确要求时才考虑。
- **久坐/空闲检测**：连续坐姿计时、`CGEventSource` 空闲时长。活动先做纯定时。
- **活动的每日目标**：每天 N 次后静默。活动先做无配额。
- **付费预设与定价**：等有真实用户后再定；当前预设随包内置，不做下载与安装。

## 12. 路线图风险

| 风险 | 影响 | 应对 |
|---|---|---|
| M1/M6 打包与签名反复 | 阻断首次可运行产物 | 先让 `swift run` 可用，打包脚本单独迭代 |
| M3 窗口与 Space 行为不达预期 | 核心体验打折 | 实测优先，允许调整层级/参数，不改产品承诺 |
| 公开仓库发布后无人问津 | 后续投入失去依据 | 发布门三条硬指标，任一为否即停 |
| 多场景默认太吵 | 第一周把用户关掉 | 活动三个固定时刻与喝水错开；日程与闹钟出厂停用；场景可停用 |
| 闹钟把产品拖成待办 | 定位被稀释 | 一次性只收未来 7 天；没有勾选、截止日与历史；过期即消失；文档明写边界 |
| M9 覆盖缺口 | 用户最常用的日历接不进来 | 文档明写支持范围；完整 CalDAV 排到延后项第一 |
| M9 解析长尾 / 协议长尾 | 某本日历整天不提醒 | 单条事件容错 + `--calendar-probe` 排查 + 失败保留缓存 + 按集合记录错误 |
| 分包后跨模块边界反复 | 拖慢开发 | 先立 Core/Scene/App 三层，场景 target 只放业务与解析 |
| 被直接复制 | 实现与素材可以被整体拿走 | 接受：护城河是迭代速度与克制，不为防抄增加任何复杂度 |
| 社区需求压边界 | 有人要求待办、统计、云同步 | 边界写死在「始终不做」；不合并不等于不礼貌 |
| 自动更新把 App 装坏 / 装不上 | 用户点完更新得到一个打不开或没变化的 App | 校验 bundle id、版本与签名后再替换；替换失败自动还原；失败在版本卡写明并给手动下载 |
