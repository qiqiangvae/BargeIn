## 1. 一句话定位

**Barge In 是一个把提醒本身当作产品的 macOS 节律工具**：常驻菜单栏，平时不存在，该喝水、该起身、该进下一场会的时候，用一套能打断心流的提醒呈现把你从工作里拽出来。

## 2. 它是什么，不是什么

| 是 | 不是 |
|---|---|
| 一个**上下文切换器**——唯一职责是在对的时刻把你从当前工作里物理性地拉出来 | 一个健康数据看板 |
| 一个**提醒呈现可配置**的引擎：三套预设、可选强度与裂纹、每个场景下都可改文案、可复制 | 又一个角标显示"该喝水了"的通知工具 |
| 一个**三场景**的节律工具：喝水、活动、日程各有一套调度与账本，同时到点也不互相吞掉 | 一个需要你手动切换场景的番茄钟 |
| 一个用**你已有的日历**决定"什么时候该打断你"的工具 | 一个日历客户端：不新建事件、不改事件、不写回 |
| 一个**零系统权限**的本地小工具，联网只在你主动开启日历时发生 | 需要账号、云同步、多端的服务 |

## 3. 需求来源与证据

### 3.1 本项目的第一手动机

> "太温柔了。我知道我要喝水，但我就是停不下来工作。"

这句话定义了产品的全部：**用户不是不知道，是做不到**。系统通知横幅、角标、轻轻一声"叮"——对这种状态的人等于零。所以起点不能温和。

### 3.2 多场景的动机

喝水与活动是两种不同的身体节律：喝水是**累计量**（今天喝到多少），活动是**定时**（到点起来舒展）。把两件事塞进一个提醒会互相污染——喝水的"第几杯"对活动没有意义，活动的"今天几次"也不该阻断喝水。所以它们是两个场景：各自调度、各自账本、各自预设实例，共用一套提醒呈现。

**日程是第三种**：它的时刻不来自本地节奏，而来自**用户已经维护好的日历**。它解决的是"我自己排的会，我照样会错过、会拖着不去"——而 Barge In 恰好有一个日历 App 给不了的东西：一个能打断心流的呈现。

同时到点不能靠"先到先得、另一个作废"：静默丢掉一条提醒是这个产品最不该做的事。v0.2 用**提醒队列**——每条都呈现，关闭一条立刻呈现下一条。

### 3.3 竞品侧的证据（详见 [competitor-scan.md](competitor-scan.md)）

| 事实 | 对产品的含义 |
|---|---|
| 硬阻断手段早已存在（`enforce`、整屏锁定、延迟解除、Strict Mode），但全是设置里的开关 | 做"更硬"不构成差异化；把"强度"做成一等公民才构成 |
| 没有任何竞品把提醒呈现层做成可更换、可配置的内容 | **最大的结构性空白**：呈现层本身就是商品 |
| 该品类头部产品把"不打扰"当政治正确（Smart Pause、自动避让） | "能打断心流"在英文区是逆风位，但也是未被占据的位置 |
| **日历在这个品类里只被用来避让**（Time Out 按日历推迟、会议期间不提醒） | 反过来用：用日历决定**什么时候该打断**，这是没人占的位置 |
| 喝水与休息分属两个品类，无人合体 | 先做两个场景，再做第三个 |
| 该品类用户的两个真实抱怨同时存在："太温柔我没注意到"与"我开始对这个 App 产生敌意" | 产品必须同时解决这两个矛盾——用**升级机制**，而不是选边 |

## 4. 目标用户

**主用户（v0.3 全力服务）**

- 每天在 Mac 前连续工作 6–10 小时的个人用户，程序员、设计师、写作者
- 知道自己该喝水、该起来活动，也认同这件事
- **日历是ta的工作表**：每天的会与专注块都在日历里，且日历是 ta 自己排的
- 试过 1–3 个提醒 App，**都在第一周把它关掉或删掉了**
- 对"被管理"敏感，对"被通知识别"极其敏感；讨厌劫持键盘、讨厌权限弹窗

**不是目标用户**

- 找健康数据、体能记录、体检建议的人
- 团队/公司（不做管理台、不做合规）
- 需要跨设备同步日历、在 App 里编辑日程的人
- 会为了"可爱"付费的人

## 5. 价值主张

对上面这类用户，Barge In 提供四件别人没有同时给的东西：

1. **能打断心流的默认档**——出厂默认就是大字墙 · 标准：满屏重复大字 + 渐强音，不是一条随时被划走的横幅
2. **越跳越硬，漏不掉的债**——每个场景各有一份账本：今天跳过三次，下次就要按住按钮才能关；完成一次就回落
3. **提醒长什么样、说什么，由你决定**——三套预设（卡片 / 满屏大字 / 满屏碎裂），大字墙可选标准或强硬、碎裂可选固定或每次不同；每个场景的每张卡片都能改文案、复制一份拿去改
4. **三个场景互不吞掉，日程也躲不过**——喝水、活动、日程各自调度；日程直接吃你已有的日历，事件开始前把你拽出来，两个会挨着也能逐条呈现

## 6. 产品原则

1. **默认值就是产品**。用户可以关掉一切，但出厂状态必须是能起作用的。日程例外地出厂停用：没有日历数据就没有意义。
2. **不劫持系统**。不拦键盘、不改系统音量、不阻止切 App、不阻止强退。提醒层展示时会短暂取得键盘焦点（双击 Esc 可中断），关闭后把前台还给原 App；强度来自"下次更硬"，不来自"这次逃不掉"。
3. **零权限**。不用通知中心、不用辅助功能、不用屏幕录制、不用 Apple Events。联网不是权限。
4. **一次交互一个动作**。完成、推迟、中断，三选一，不需要学习。队列里的每一条仍然是这条规则。
5. **默认不联网，数据只在本机**。日程订阅是唯一的例外：只读、可选、默认关，只访问用户自己填的地址，不上传任何内容、无遥测、无账号体系。
6. **升级要有解释**。界面上永远告诉用户"你为什么现在被这样对待"，并且说清是哪个场景。
7. **不静默丢弃**。多场景同时到点逐条呈现；网络断了就按缓存提醒并明说数据可能过期，绝不因为没有网络就把一条日程抹掉。
8. **场景是对称的**。三个场景都有启用开关、预设实例与账本；"取数方式"不同，待遇不降级。

| 违规账本 | 跳过累计 → 4 级升级 → 完成回落 → 次日归零 |

| 设置窗口 | 单窗口、分 tab、即时生效，每张预设卡都能单独预览 |
| 兜底 | 免打扰 1 小时、开机自启 |

### v0.1.1（预设实例）

- 每个场景出厂三张卡：温柔、大字墙（强度默认标准）、碎裂（裂纹默认固定），默认激活大字墙
- 卡片可编辑：强度（仅大字墙）与文案槽，带可用变量提示与"恢复默认文案"
- 卡片可复制：同场景深拷贝一份；副本可删，内置三张不可删
- 设置分两级：一级只显示前 3 张卡 + 「全部 N 个」入口，二级展示全部预设
- 首次启动：在温柔 / 大字墙里二选一（默认大字墙），点"就用这个"后立即真实呈现一次预览

### v0.2（多场景 + 活动）

| 功能 | 说明 |
|---|---|
| 两个场景 | 喝水（累计量、达标静默）与活动（纯定时、起身舒展、无配额） |
| 按场景配置 | 每个场景有自己的调度、预设实例、账本、启用开关；工作时段、休息日、免打扰全局共享 |
| 提醒队列 | 同时到点逐条呈现；每场景最多一条待处理；提醒层显示"还有 N 个提醒" |
| popover 双场景 | 水位环 + 活动条；停用的场景整块隐藏 |
| 分包 | 场景无关引擎、喝水、活动、App 层四个 SwiftPM target |

### v0.3（日程，本版）

| 功能 | 说明 |
|---|---|
| 第三个场景 | 日程：订阅你已有的日历，事件**开始前 N 分钟**（默认 5）把你拽出来 |
| 只读取数 | 两种来源，都只读：**一条日历地址**（Google 秘密地址、iCloud 公开共享、Outlook 发布链接、Nextcloud 公开分享），或**一套 CalDAV 凭据**（钉钉、企业微信、飞书、iCloud 私有、Fastmail、Nextcloud）。支持多条、可分别启用 |
| 只读的边界 | 只发读请求（`GET` / `PROPFIND` / `REPORT`），不写回、不创建、不删除、不读参会人、不碰会议链接 |
| 与系统日历的关系 | 系统日历告诉我"有个会"；Barge In 负责"现在，停下你手上的事" |
| 豁免工作时段 | 19:00 的会、周六的日程照常提醒；免打扰仍然生效 |
| 队列按事件 | 两个会挨着也能各提醒一次，逐条呈现，"还有 N 个" |
| 失败不丢提醒 | 拉取失败按上次缓存继续提醒，界面标注"数据可能过期"；认证失败单独提示 |
| 完成动作 | 「知道了」：不写回、不改事件，只记账 |
| 出厂默认 | 日程**停用**；添加订阅并成功拉取后提示开启 |

## 8. 已锁定的关键产品决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 平台 | 仅 macOS，原生 Swift | 用户是 Mac 个人用户；跨平台抽象是双倍成本换零收益 |
| 形态 | 菜单栏 + 提醒层 + 独立设置窗口 | 90% 的交互发生在被提醒的 10 秒，其余时间应当不存在 |
| 喝水模型 | 配额（日目标 + 进度） | 累计量与"连续坐姿时长"是两种不同模型，不强行统一 |
| 活动模型 | 纯定时，无配额、无久坐检测 | "到点起身舒展"是用户能理解的动作 |
| 日程模型 | 事件前置提醒，不是日历客户端 | 产品只负责打断，不负责排期；写回会让它变成半个日历 |
| 日程取数 | **两条只读传输：日历地址（ICS）与 CalDAV 账户** | 钉钉、企业微信、飞书、iCloud 私有都只给 CalDAV 凭据，一条 GET 拿不到；两种传输在解析层同构，多写一层不多写一套模型 |
| 日程的默认 | 前置 5 分钟；**出厂停用**；默认大字墙 · 标准 | 没有订阅就没有数据；提醒发生在会前，你还在独自工作 |
| 日程 vs 工作时段 | 日程**豁免**工作时段与休息日 | 19:00 的会与周六的日程不该被静默吞掉；事件自带时间 |
| 队列去重键 | `(场景, 事件标识)` | 喝水与活动行为不变；日程按事件各一条，不丢提醒 |
| 日程的"完成" | 「知道了」，不写回日历 | Barge In 不知道你有没有真去开会，也不该假装知道 |
| 联网 | 只破"零网络"这一条，只读、可选、默认关 | 见 [ADR-0001](adr/0001-network-for-calendar-subscriptions.md) |
| 凭据 | URL 里的 token 随地址存；用户名密码进 Keychain | 地址本身即凭据；密码不能进 `UserDefaults` |
| 失败策略 | 保留缓存继续提醒 + 明确标注过期 | "不静默丢弃"优先于"数据绝对新鲜" |
| 同时到点 | 提醒队列，逐条呈现，不静默丢弃 | 后续场景可能有强感知要求 |
| 合并呈现 | 本期不做，等用户需求 | 需要重新定义"主场景 + 附加行"的呈现与记账 |
| 节奏 | 固定间隔或指定时刻，不做动态追赶 | 用户痛点是"停不下来"，不是"节奏不对" |
| 呈现 | 三套预设（温柔 / 大字墙 / 碎裂），大字墙带强度、碎裂带裂纹，出厂默认大字墙·标准 | 三套资源覆盖"卡片"、"打断"与"砸醒"三种需求 |
| 预设资源 | 与场景解耦，三个场景共用 | 场景只提供默认文案与变量 |
| 强度与裂纹 | 预设只能选档位，不能改数值 | 拦截输入=恶意软件语义；惩罚类机制高卸载 |
| 中断 | 永远即时生效 | "可立即中断"是硬需求；队列也不取消后续 |
| 分发 | 开源 + SwiftPM 构建 + 官网 DMG | 能力不受沙盒限制；开源是获客与信任的来源 |
| 收费 | 核心功能全部免费开放，少数资源（预设）买断下载 | 内容可被 fork，护城河是内容质量与更新节奏 |
| 商业定位 | 个人副业，收入是副产品 | 品类天花板在副业量级 |

## 9. 提醒体验体系

**档位的来源**：不是四套预设，而是三套预设 + 大字墙的强度；碎裂固定取"大字墙 · 标准"那一行。四个档位是：温柔 / 大字墙 · 标准 / 大字墙 · 强硬 / 碎裂。

**三段式强度**

- 起点 = 当前场景激活实例的档位
- 加码 = 该场景今日跳过次数（4 级）
- 回落 = 完成一次减一级，次日归零

**档位表**（预设只能选强度，不能自定义数值）

| 档位 | 呈现 | 推迟 | 中断按钮 | 中断方式 |
|---|---|---|---|---|
| 温柔 | 右上角卡片 + 单次提示音 | 允许 | 立即可点 | 双击 Esc 或单击 × |
| 大字墙 · 标准 | 满屏重复大字 + 渐强音 | 允许 | 立即可点 | 双击 Esc 或单击 × |
| 大字墙 · 强硬 | 满屏重复大字 + 渐强音 | 禁止 | 延迟 5 秒 | 双击 Esc 或单击 × |
| 碎裂 | 满屏碎玻璃 + 玻璃碎音 | 允许 | 立即可点 | 双击 Esc 或单击 × |

**升级曲线**

| 级别 | 音效 | 推迟 | 中断按钮 | 中断方式 |
|---|---|---|---|---|
| 0 | 档位值 | 按档位表 | 按档位表 | 双击 Esc 或单击 × |
| 1 | 档位值 | 允许 | 延迟 5 秒 | 双击 Esc 或单击 × |
| 2 | 100% 立刻 | 禁止 | 延迟 10 秒 | 双击 Esc 或单击 × |
| 3 | 100% 立刻 | 禁止 | 延迟 10 秒 | 双击 Esc 或按住 × 2 秒 |

**Esc 一律双击**：任何档位、任何等级都要在 1 秒内连按两次才中断，单击不生效；延迟还没走完时双击照样立即中断。× 按钮 0–2 级解锁后单击即可，第 3 级要按住 2 秒。

**账本按场景各一份**：跳过喝水只加码喝水。升级说明带场景名——"今天已跳过 3 次日程提醒，中断按钮延迟 10 秒"。

**队列**：多个场景同时到点时，先到先呈现；当前关闭后立即呈现下一条，并显示"还有 N 个提醒"。每条用自己的预设与账本；中断当前一条只记当前场景的跳过，不取消后面的。

**日程的呈现**：`大字词` 就是事件标题（"Q4 产品评审"铺满屏），进度行是"{start} 开始 · 还有 {minutes} 分钟"。它不需要像喝水那样给出"该做什么"——日历已经说了。

**视觉冲突**：大字墙是满屏重复的大字墙——大小字混排、7° 倾斜、每词各自旋转偏移、5 组错峰闪到全亮。冲突来自密度、凌乱与闪烁。

**为什么这样设计**：它同时回应"太温柔我没注意到"与"我开始对它产生敌意"两种抱怨——平时不暴力，暴力只在你反复无视它之后出现，且出现前有明确预告。

## 10. 交互概要

- **首次启动**：设置窗口 + 温柔 / 大字墙二选一（默认大字墙，强度标准），这次选择同时落到三个场景；点"就用这个"后**立即按喝水场景真实呈现一次预览**（带一行"这是预览"标识；任何动作只关闭，不写状态不记账），随后窗口关闭、只剩菜单栏
- **日常**：只在菜单栏；点开看喝水进度、活动次数与下一场日程，点水位环记一杯、按住环 2 秒清空今日进度，免打扰 1 小时，或点"活动了"，进设置
- **被提醒**：满屏重复大字或右上卡片，一个动作结束；快速双击 Esc 随时中断；"完成"不受关闭延迟影响，也可在 1 秒内连按两次 Enter
- **同时到点**：逐条呈现，每一条底部显示"还有 N 个提醒"；关掉一条立刻下一条
- **日程**：在设置「日程」tab 里贴订阅地址 → 立即同步一次 → 看到"已同步 N 个事件" → 打开场景开关。地址失效或密码错，行内直接说原因，不去猜"网络错误"
- **设置**：单窗口两级，顶部「喝水 | 活动 | 日程 | 设置」——场景页是当前场景的预设前 3 张 + 场景参数（喝水有配额、活动有节奏、日程有订阅与前置），设置页是喝水与活动共用的时间与开机自启；二级是当前场景的全部预设
- **停用**：每个场景页顶部有"启用这个场景"开关；停用只停调度，不清账本与进度

详细规格见 [技术方案 §5](design.md)。

## 11. 开源与商业模式

**开源策略**

- 仓库整体 MIT，代码全公开，功能全开，代码里不存在任何付费判断
- 未来付费内容是**预设**（视觉做法、音效、文案），不是能力阉割
- 付费预设从官网分发，不进入公开仓库

**收入**

- 唯一收入来源：官方预设买断（单套 / 系列 / 全解锁）
- 不做订阅、不做账号、不做内购
- v0.3 不做市场、不做下载、不做预设的安装与卸载；定价在 v0.4 之前不做决策，也不写进文档

**为什么开源**

1. 开源是获客：这个品类的头部（Stretchly）靠开源建立信任与传播
2. 开源让"内容收费"可信：用户能看到引擎怎么工作，买的是做得好，不是被锁住
3. 开源降低支持成本：用户能自己看代码、自己提 PR

**必须承认的代价**：代码可被 fork；收入量级低于闭源头部的 $5k/月。这是选择这条路的已知成本，不为此增加任何防御机制。

## 12. 度量

**不做遥测**。因此可观测的只有：

| 指标 | 含义 |
|---|---|
| Release 下载量 | 有没有人真的想试 |
| GitHub star / issue 质量 | 问题是不是"有价值的问题" |
| 付费预设销量 | 唯一的商业验证 |
| 自己每天还在用吗 | 产品的第一号测试 |

**成功的定义（v0.3）**：自己连续用满两周，三个场景都没有被关掉，日程订阅一直在刷；且有陌生人在 issue 里提具体的功能请求。

## 13. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **默认值风险** | 这个品类的用户第一周就会关掉提醒。默认温和 = 产品回到起点 | 出厂默认"大字墙 · 标准"；活动三个固定时刻；日程出厂停用 |
| **场景太吵** | 三个场景叠加，第一周就把用户赶走 | 活动与喝水错开；日程只在你真有会时才触发；每个场景有启用开关；同时到点逐条呈现但不合并 |
| **日程覆盖缺口** | CalDAV 覆盖了钉钉/企业微信/飞书/iCloud 私有，但 Google 私有与 Outlook 私有仍需 OAuth 或 Graph | 文档与设置页明写支持范围；不假装能通吃，把这两家放进延后项 |
| **联网叙事受损** | "零网络"曾是一句干净的卖点，现在要多解释一句 | 只读、可选、默认关、凭据进 Keychain、可自证；README 与设置页明写，不藏 |
| **凭据失效** | 秘密地址被重置、钉钉里重新生成了 CalDAV 密码，用户看到"没日程了"却不明白 | 认证/格式错误与"今天真没日程"分开说；连续失败退避并在界面上留痕 |
| **两套日历** | 系统日历的提醒同时响，变成双重打扰 | 文档说明定位差异：关掉系统日历的事件通知，或让 Barge In 只订阅工作时间那本日历 |
| 合并需求 | 有人嫌几条连着弹 | 本期不做；先观察 |
| 付费意愿低 | 开源 + 内容收费的付费率极低 | 接受它：收入是副产品 |
| 被 fork | 代码公开，可被复刻 | 不防御 |
| 单人时间不足 | 副业，时间碎片化 | 里程碑按"可中断的周末块"切分 |
| 平台兼容 | 构建依赖 CLT，无完整 Xcode | 只用系统稳定 API；不引入第三方依赖 |
| 签名与公证 | 无 Developer ID 证书 | v0.3 面向开发者；v1.0 再买证书做公证 |

## 14. 竞争与可行性结论

**竞争力**：真正的差异化不在"更硬"，而在**提醒呈现层被当作产品来做**——竞品把硬阻断藏在 JSON 开关里，把提醒样式写死在代码里。Barge In 把呈现做成第一等公民，再叠加三个场景与"用你自己的日历决定何时打断你"这个反过来的用法。

**可行性**：技术上全部使用系统自带能力，无后端、无账号、无遥测；唯一的复杂度集中在日程的 ICS 解析与订阅失败处理，已被压到"一条 GET + 可选 Basic Auth"。商业上量级有限但真实，因此立项定位为副业。

**一句话结论**：这是一个**天花板不高但确定存在、投入可控、且有一个别人没占的位置**的产品。
