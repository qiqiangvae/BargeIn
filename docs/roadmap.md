## 0. 路线图的基本立场

1. **里程碑不是时间表**。工作量以"人日"给出量级估算（单人 + AI 辅助），不承诺日历日期。每个里程碑都是**可中断点**：做到哪一步停下，都是一个能用的东西。
2. **一次只开一条链路**。v0.1 只做喝水；v0.2 才让活动成为第二个场景；v0.3 才让外部日历成为第三种触发来源。任何"顺手把完整 CalDAV 也做了"的念头都推后。
3. **每个里程碑都有一个可验收的产物**，不是"写完了代码"。验收不过就不进下一个。
4. **商业决策（定价、商店、付费包）一律推迟到 v0.4 开始前**，v0.1–v0.3 的代码里不出现任何付费、市场、下载相关的东西。

## 3. v0.1 — 只做喝水

### M1 骨架（1–2 人日）— 完成

**交付物**：SwiftPM 工程、`Info.plist`（`LSUIElement`）、`scripts/bundle.sh`、`Makefile`、菜单栏图标、popover 空壳、`AppState` 持久化。

**验收**
- `make app` 一条命令产出 `Barge In.app` 并能启动
- 启动后无 Dock 图标，菜单栏有图标，点开能看到空 popover
- 改一个状态 → 退出 → 重启，状态还在

### M2 喝水闭环（2–3 人日）— 完成

**交付物**：配额状态（目标/单杯/已喝/跨日重置/达标静默）、`Schedule`（间隔 + 指定时刻）、工作时段、休息日、`nextFireDate` 定时器与唤醒/改时重算、popover 进度显示。

**验收**
- 改设置后下一次触发时间立即正确
- 达标后当天不再提醒；次日自动重置
- 非工作时段、休息日、暂停中均不提醒
- 唤醒后若已过点，只补触发一次

**风险**：跨日、睡眠、时区跳变是这类 App 的三个经典坑。全部在 `Schedule` 一个地方处理，不在 UI 层兜底。

### M3 呈现体验（3–4 人日）— 完成

**交付物**：`NSPanel` 多屏覆盖（`screenSaver` 层级、跨 Space）、卡片样式、满屏重复大字的全屏样式、音效（含渐强）、三个动作（完成/推迟/中断）、双击 Esc 与按住中断。

**验收**
- 多显示器全覆盖；切 Space 不丢失；全屏 Space 内能弹出
- 三种结束方式各自生效；中断零等待
- 任何档位下单击 Esc 都不中断，快速双击 Esc 可立即中断；强档下按住 × 2 秒也可中断
- 提醒展示中再次到点不叠面板
- 拔插显示器后面板集合正确重建

**风险**：这是唯一的"看起来简单、坑最深"的里程碑。窗口层级与 Space 行为以实测为准。

### M4 账本升级（1–2 人日）— 完成

**交付物**：跳过计数、4 级参数覆盖、完成回落、次日归零、界面上的升级预告文案。

**验收**
- 连续跳过按表逐级加码；完成一次回落一级，下限 0；次日归零
- 每次提醒都能看到"为什么现在是这一档"
- 三个档位各自的上限生效（温柔 1 级、大字墙 · 标准 2 级、大字墙 · 强硬 3 级）

### M5 设置与引导（2–3 人日）— 完成

**交付物**：设置窗口全部配置项、首次启动一步完成预设选择（默认大字墙）、开机自启、免打扰 1 小时。

**验收**
- 所有配置即时生效，没有保存按钮
- 首次启动一步完成，不做多步引导
- 重启 App 后所有配置保持

### M6 开源发布 v0.1（1–2 人日）— 完成（待推送）

**交付物**：README（截图、`make app` 三步上手）、LICENSE（MIT）、`.gitignore`、GitHub Release 附 `.app` 压缩包与构建说明。

**验收**
- 陌生机器 `git clone` → `make app` → 能运行
- README 里没有任何需要用户关掉安全机制的步骤
- 自己连续使用 7 天没有关掉提醒

**发布门（决定是否继续投入）**

发布后观察四周，三个问题全部为"是"才继续：

1. 我自己还在用它吗？
2. 有陌生人提了**具体的**功能请求（而不是 star）吗？
3. 有没有人问"有没有别的效果"（验证呈现层是商品这一核心假设）？

## 4. v0.1.1 — 预设实例

### M7 预设实例（1–2 人日）— 完成

**交付物**：预设实例模型、文案槽与变量、引擎档位表、设置两级页面（一级固定前 3 张 + 「全部 N 个」入口，二级全部预设 + 返回）、卡片编辑（名称 + 强度 + 文案槽，内联展开）、复制、改名与删除、首次启动二选一 + 立即预览、账本按场景。

**验收**
- 设置里能改文案，改完立即作用于预览与真实提醒
- 能复制出一张卡；副本只出现在当前场景，复制不切换激活
- 副本可删；删除正在使用的副本回落大字墙；内置两张没有删除入口
- 预设变多时一级页面高度不变，全部实例在二级页滚动
- `--selftest` 覆盖文案槽渲染与未知变量回落

## 5. v0.2 — 多场景 + 活动

### M8 多场景 + 活动（4–6 人日）— 完成（待合并）

**交付物**：SwiftPM 分包（`BargeInCore` / `SceneWater` / `SceneActivity` / `BargeIn`）、场景模型（`SceneID`/`SceneDescriptor`/`SceneConfig`）、活动场景、全局共享时间、按场景的队列与调度、popover 双场景、设置按场景切换、引导落到两个场景。

**验收**
- 两个场景各自调度、各自账本，互不牵连
- 同时到点：先到先呈现，关闭后立即呈现下一条，显示"还有 N 个"
- 每个场景最多一条待处理；唤醒只补同一天、工作时段内、未暂停的到点
- 停用一个场景只停它的调度，另一个照常
- `make app` / `--selftest` / `--snapshot` 全部通过

## 6. v0.3 — 日程

### M9 日程（6–9 人日）— 规划中

**前置**：v0.2 已完成；产品方向已锁定（见 [product.md §8](product.md)）——只读订阅、事件前置提醒、不写回、不做完整 CalDAV。

**交付物**

- `SceneID.schedule` + `SceneTrigger`（`rhythm` / `events`），`FirePlan` 支持事件来源与"开始超过 10 分钟不补"
- `SceneSchedule` target：iCalendar 子集解析（行折叠与转义、`UID`/`SUMMARY`/`DTSTART`/`LOCATION`/`RRULE`/`EXDATE`、`TZID`/UTC/`VALUE=DATE`）、`DAILY/WEEKLY/MONTHLY + INTERVAL + COUNT/UNTIL/BYDAY` 展开、事件窗口 `[now-1d, now+8d]`
- 传输一（ICS）：`GET` + 可选 Basic Auth、`webcal://` 改写、`Content-Type` 校验
- 传输二（CalDAV）：`PROPFIND` 发现日历集合 → 用户勾选 → `REPORT calendar-query` 拉事件；钉钉 `calendar.dingtalk.com` 为首个验收目标，企业微信/飞书/iCloud 私有/Nextcloud 同构
- 订阅：多条来源（地址或 CalDAV 账户）、密码进 Keychain、串行请求、30 分钟刷新 + 唤醒刷新 + 手动刷新、失败退避到 4 小时、取回的日历文本缓存到 `Application Support`
- 失败降级：读缓存继续提醒 + 设置页与 popover 标注过期；认证/格式/网络三类错误分别给文案
- 队列：去重键改为 `ReminderKey(scene, eventKey?)`，日程按事件各一条
- 已提醒去重：`handledEventKeys` 落盘按天清理；推迟用 `snoozedUntil`（进程内）
- UI：设置第 4 个 tab（订阅列表 + 前置 + 预设，无节奏卡）、popover 日程行、日程卡预览占位事件
- 默认值：场景出厂停用、前置 5 分钟、默认大字墙 · 标准
- `--selftest`：解析、展开、豁免规则、按事件去重的队列、失败降级、已提醒不重弹
- `--calendar-probe`：`ics <url>` 或 `caldav <server> <username> --discover`，只取一次并打印解析结果，用于排查订阅

**验收**

- **真实钉钉 CalDAV 账号**：填入服务器/账号/密码 → 发现日历 → 拉到事件 → 事件开始前 5 分钟提醒；在钉钉里改事件时间 → 30 分钟内同步
- 填真实 Google 秘密地址（ICS 传输）→ 同样命中正确时刻
- 断网重启 → 仍按缓存提醒，设置页明说数据可能过期
- 地址写错 / CalDAV 密码错 / 返回 HTML → 分别提示"地址无效""认证失败""格式无法解析"，不弹提醒也不崩
- 19:00 的会议、周六的日程照常提醒；免打扰期间不提醒
- 两个事件相隔 5 分钟 → 逐条呈现，"还有 N 个"正确
- 全天事件不提醒；已开始超过 10 分钟的事件不补弹
- 同一事件重启 App 后不重弹
- `make app` / `--selftest` / `--snapshot` 全部通过

**不做**：CalDAV 写操作（PUT/DELETE/MKCALENDAR）、`sync-token` 增量、OAuth、Graph、写回日历、全天事件、参会人与会议链接。

**风险**

- **覆盖缺口**：CalDAV 覆盖钉钉/企业微信/飞书/iCloud 私有/Nextcloud，但 Google 私有与 Outlook 私有仍要 OAuth 或 Graph。文档明写支持范围，不承诺通吃。
- **钉钉 CalDAV 未实测**：服务器地址与 home set 形态来自实践文档与开源实现。M9 第一件事就是拿真账号跑通，跑不通先修传输层，不靠改叙事绕过。
- **解析长尾**：真实 `.ics` 里格式千奇百怪（非标准时区、非法折行、缺少 `DTEND`、`RRULE` 长尾）。策略是"解析不出的单条事件跳过并计数，整本失败才报错"，不让一条脏数据拖垮整天。
- **联网叙事**：产品第一次联网，容易被当作"开始变味"。对策是只读、默认关、凭据进 Keychain、README 明写。
- **地址失效**：秘密地址被重置后用户只会看到"没日程了"。对策是错误原因与"今天真没日程"分开说。

## 9. 始终不做

统计图表、连续达标天数、成就、云同步、账号、遥测、iOS 端、摄像头确认、Apple Watch、AppleScript/Shortcuts 钩子、全局快捷键自定义、会议/录屏自动避让、代码级插件系统；预设的安装与卸载、manifest、目录扫描、素材运行时、字号配置；日程的写回与编辑、全天事件提醒、参会人与会议链接。

## 10. 延后项（等真实需求）

- **Google 私有 / Outlook 私有的取数**：前者要 OAuth 2.0 + 企业 MS 生态的 OAuth 客户端，后者只有 Microsoft Graph。它们是 v0.3 之后最可能被要求的一件事，但都不是"多写一个分支"的量级。
- **合并呈现**：同时到点只弹一次、把多个场景放进同一面板。需要先定义"主场景 + 附加行"的呈现与记账规则。
- **优先级策略**：只提醒一条、其余记为已提醒。与"不静默丢弃"冲突，只有真实用户明确要求时才考虑。
- **久坐/空闲检测**：连续坐姿计时、`CGEventSource` 空闲时长。活动先做纯定时。
- **活动的每日目标**：每天 N 次后静默。活动先做无配额。

## 11. 路线图风险

| 风险 | 影响 | 应对 |
|---|---|---|
| M1/M6 打包与签名反复 | 阻断首次可运行产物 | 先让 `swift run` 可用，打包脚本单独迭代 |
| M3 窗口与 Space 行为不达预期 | 核心体验打折 | 实测优先，允许调整层级/参数，不改产品承诺 |
| v0.1 发布后无人问津 | 后续投入失去依据 | 发布门三条硬指标，任一为否即停 |
| 多场景默认太吵 | 第一周把用户关掉 | 活动三个固定时刻与喝水错开；日程出厂停用；场景可停用 |
| M9 覆盖缺口 | 用户最常用的日历接不进来 | 文档明写支持范围；完整 CalDAV 排到延后项第一 |
| M9 解析长尾 / 协议长尾 | 某本日历整天不提醒 | 单条事件容错 + `--calendar-probe` 排查 + 失败保留缓存 + 按集合记录错误 |
| 分包后跨模块边界反复 | 拖慢开发 | 先立 Core/Scene/App 三层，场景 target 只放业务与解析 |
| v0.4 破坏开源叙事 | 信任受损 | 实现前先写清公开边界，引擎与预设格式永久开源 |
