# 日程订阅是唯一的联网功能

Barge In 的产品叙事里锁过一条"零权限、零网络、零账号，全部数据只在本机"。日程场景必须从外部日历取数，这条原则第一次被打破。结论：只破"网络"这一条，且严格限定为**用户自己填写的只读订阅地址，出站 GET，不上传任何数据**。

这条决定难回退——它是产品对用户的承诺，一旦说出口就不能悄悄扩大；它也让后来的人意外——代码里出现网络请求与一个"零网络"的招牌并存；它是一次真实权衡——另一条路是让用户自己把 `.ics` 导出到本地，技术上干净但产品上不成立。

**允许**：用户主动添加的日历地址，或用户自己在日历服务里生成的 CalDAV 凭据；只读操作（`GET`、`PROPFIND`、`REPORT`）；可选 Basic Auth；凭据存 Keychain；停用或删除订阅即停止访问。

**不允许**：内置任何日历服务的对接、OAuth、账号体系、写回日历、任何写操作（`PUT` / `DELETE` / `MKCALENDAR`）、增量同步令牌、遥测、崩溃上报、任何非用户填写的出站请求。日程场景出厂停用，未配置订阅时不存在任何请求。

**代价**：这是产品第一次向外部世界发请求，"零网络"从一句干净的卖点变成一个需要解释的例外。README、设置页与产品原则都必须明写，而不是藏起来。
