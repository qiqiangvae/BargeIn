# 凭据默认存本地配置文件：换版本不再重新授权

产品从 v0.3 起把日程密码存系统钥匙串（[ADR-0001](0001-network-for-calendar-subscriptions.md)），代价是**每次更新后都要重新授权一次**（用户反馈的原话：「每次更新都要授权，太麻烦了」）。结论：日程密码默认改存本地配置文件 `~/.config/bargein/config.toml`（权限 0600，明文），钥匙串降为设置里的可选项；切换时由 App 搬密码，用户不重填。

**为什么**

- ad-hoc 签名每版都变：它的 designated requirement 是 `cdhash H"…"`，重新构建即换。钥匙串的「始终允许」绑在签名身份上，于是更新后的新版本被系统当成陌生 App，弹一次「想要使用你存储在钥匙串中的机密信息」；这一下授权只对刚才那个身份有效，所以下一版还会再弹。
- 这条约束只有两种断法：让签名身份稳定（Developer ID + 公证，要开发者账号与年费，属 v1.0 发布事项），或不再让系统按签名身份授权（本地文件）。本版选后者：不花钱、不依赖证书，代价是明文。
- 明文风险必须写在明处，而不是在设置里含糊过去：0600 与 0700 只挡别的用户，挡不住同一用户下的进程、Time Machine 与同步盘备份。

**怎么做**

- 文件 `~/.config/bargein/config.toml`，只有一个 `[passwords]` 表：键 = 订阅 id，值 = 密码。目录 0700、文件 0600、临时文件 + rename 原子写；读的时候坏行与别的表一律跳过，不当错误。
- `AppState.credentialStore` 记录模式，出厂 `.file`；设置·通用「凭据存储」二选一，行下一句写明路径、明文性质与两种模式的差别。
- 切换模式：写新存储 → 读回核对 → 删旧存储；任一条没搬成（例如钥匙串授权被取消）就留在原处、模式不切，卡里给一行说明。
- 升级迁移：文件模式下取密码时，文件里没有就从钥匙串读一次、写进文件、删掉钥匙串条目。这一次授权不可避免，但只发生一次，用户点完「始终允许」之后长期静默。
- `Credentials` 是唯一入口；`FeedService` 与设置里的添加 / 删除订阅都走它，两种模式对上层没有分支。

**边界**

- 只管日程密码。ICS 地址里的 token 属于地址本身，仍在 `AppState` / `UserDefaults`，不进文件也不进钥匙串。
- 文件不加密；App 是唯一写者，手改会被整体覆盖。
- 删除订阅同时删文件里的条目与钥匙串里的残留副本，避免切回钥匙串时复活一个旧密码。
- 选「钥匙串」的用户仍会遇到每次更新后的重新授权——那是他们选的档，不是 bug。

**代价**

- 破掉「凭据进钥匙串」这句安全叙事：README、`docs/product.md`、`docs/design.md` 与 [ADR-0001](0001-network-for-calendar-subscriptions.md) 的凭据结论同步改写。
- 密码对同用户进程与备份可见；这是为「换版本不再授权」付的账，写在设置里而不是藏起来。

**被否掉的方案**

- **固定自签名证书**（让 DR 稳定为 `identifier "com.bargein.app" and certificate leaf = H"…"`）：实测跨构建不变，且在没有证书的机器上 `codesign --verify --deep --strict` 仍通过、按证书要求匹配也能过，理论上同样能止住弹窗。放弃的原因：要长期保管私钥、迁移时用户仍被问一次、切到 Developer ID 时再问一次，而 Gatekeeper 的拦截一点没变——复杂度换不到完整收益。
- **Developer ID + 公证**：能同时解决 Gatekeeper 与钥匙串，需要年费与账号审核，属 M12 正式发布，不阻塞本版。
- **更新后自动重写钥匙串条目**：写条目本身同样要授权，绕不开。
