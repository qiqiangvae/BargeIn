# 不做自动升级：强度属于预设，账本只记录

v0.1 起，产品有一套"跳过越多越硬"的账本：每个场景记跳过次数，按 4 级加码，完成一次回落，次日归零；提醒层与设置里展示升级说明。它解决的是"心流用户会反复点推迟"。

结论：**删除自动升级**。强度不是账本的产物，而是预设实例自己的可配置项——只有大字墙有强度（标准 / 强硬），它和文案覆盖同级，由用户自己改。账本只记录（进度、完成、跳过、已处理），不参与任何呈现决策；产品不做自动加码、额度或反制。

**为什么**

- 强度属于"呈现长什么样"，而呈现归预设；把强度和跳过历史绑在一起，等于让同一个预设在不同的日子长得不一样，用户无法预期。
- 自动加码把"惩罚"写进产品：用户越忙，提醒越难关，这和"提醒是帮助，不是管理"冲突。
- 没有升级之后，"推迟"就是用户的选择：默认大字墙 · 标准允许推迟，要更狠就选强硬（不可推迟）。产品不为用户的选择兜底。

**代价**

- 价值主张里"越跳越硬，漏不掉的债"消失；产品少了一个反制心流的手段。
- 心流用户可能一直点推迟。这是接受的取舍：靠默认值与预设本身，而不是靠一个用户看不见的算法。
- 代码里不再有等级合成与升级说明：`Ledger`、`PresentationBuilder` 一并删除，呈现只由预设实例决定；M4 从"账本升级"改为"账本记录"。

**被否掉的方案**

- 保留账本但给升级封顶：仍然是产品在背后改变呈现，只是幅度小，用户同样无法预期。
- 每日推迟额度：不是升级，但仍是用记录反制用户。
