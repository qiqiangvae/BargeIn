# 闹钟与日程是两个场景

v0.4 加了一个"用户自己定时刻"的场景（闹钟），它的形状和一个日程事件几乎一样：一个时刻加一句内容，到点打断。另一条路是把两者合并成一个"事件提醒"场景、用"来源"区分订阅与本地。结论是**拆成两个场景**：两者对通用时间的待遇相反（日程豁免工作时段与休息日，闹钟受其约束），取数边界也相反（日程只读外部、从不写回；闹钟的列表是本机可写数据），而场景同时是账本、启用开关、预设实例和设置页的归属单位。

**被否掉的方案**：一个场景 + `来源` 字段。它省一个场景，但会把"受通用时间约束"变成按来源分支的条件，并把 ADR-0001 守住的"只读外部日历"稀释成"其中一种来源"，两种东西的默认前置、默认文案、列表编辑器也挤在同一页。

**代价**：两处几乎一样的列表 UI，两个事件源的装配点。队列键 `(场景, 标识)` 与呈现层不变，所以重复的只有外壳。

**实现上的约束**：`SceneTrigger` 给闹钟一个独立 case，不复用 `events(leadMinutes:)`——`trigger` 被当作场景身份参与存档容错（读不出来整块回出厂），两个场景共用同一个取值会被认错。
