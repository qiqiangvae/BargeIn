# 源码进入公开仓库，采用 MIT 开源

0.4 的发布模型是「核心代码暂不公开，公开仓库只放 App 与文档」（[ADR-0004](0004-release-model-private-core.md)）。0.4.1 改为：**源码与文档放进同一个公开仓库，MIT 许可，不再保留私有开发仓。**

**为什么**

- 承诺要能被验证。源码公开是"零权限、零网络、不做自动升级"这些边界最硬的证据，比任何文档都直接。
- 这个产品没有靠保密成立的护城河：复杂度集中在呈现与调度，抄走实现不会让任何人少走这段路；护城河是迭代速度与克制。
- 两套仓库的代价已经付过一次：0.4 纠偏时代码与公开仓文档对不上，官网还在讲已经删掉的机制。单仓库是唯一不会再犯的结构。

**允许**：公开源码、文档、issue 与更新记录；任何人按 MIT 使用、修改、分发，包括商业使用。

**不允许**：把"开源"当卖点；把社区热度当作扩大产品边界的理由（边界以 [product.md](../product.md) 为准）。

**代价**

- 实现与素材会被整体拿走；别人可以做出更商业化的变体。
- 社区会提出与定位冲突的需求：待办、统计、云同步。拒绝会消耗口碑。
- MIT 一旦发布就无法收回；已公开的提交不能再变回私有。

**被否掉的方案**

- 保持私有核心、只发二进制：失去可验证性，且两套仓库继续各说各话。
- 私有核心 + 以后开源：即 ADR-0004 的方案，"以后"没有日期，等于没有承诺。
- 源码公开但改用非 MIT 的自定义许可：增加理解成本，换不来实际保护。
